# #319 develop 기반 동물 경제 API 연결·QA

## 기준과 범위
사용자가 이번 작업 PR들을 develop에 병합하고 develop 기준으로 프론트·백엔드를 연결해 QA하도록 지시했다. 백엔드 #273(develop 9dffc812), 프론트 #311(develop 869b8d12)을 병합했다. 동물 UI #316·등장/실루엣 수정 #318은 이미 develop에 반영되어 있었다. 원래 작업 폴더의 미커밋 변경은 그대로 두고 develop worktree에서 구현했다.

## 연결
- 인증된 개발 화면은 1200 체험 포인트·임의 보유 동물 대신 서버 지갑/보유/정원으로 시작한다. 서버 확인 전에는0P/빈 목록이며 실패 시 로컬 지급하지 않는다.
- 카탈로그, 전체 보유 페이지, 배경 소유권, 정원 version/상대 좌표, 현재 뽑기 풀과 확률, 판매가, 뽑기 이력을 실제 API에서 조회한다. 기본 배경은 null로 저장하며 미보유 배경은 적용할 수 없다.
- 뽑기 결과는 서버가 정하고 연출은 응답 이후 시작한다. 판매와 배치·교체·해제도 서버 성공 이후 갱신한다. 포인트는 서버 잔액만 사용하며 캠퍼스 일간 누적 보상을 더하지 않는다.
- draw/sale의 Idempotency-Key와 본문을 계정별 SecureStore에 먼저 저장한다. 성공 응답 확인 전까지 유지하고 재조회/다음 실행 시 같은 키로 결과 복구한다. 새 거래는 기존 미확정 요청 처리 후 가능하다. 서버 확정4xx는 pending을 제거하며 네트워크/5xx/파싱 실패는 유지한다.
- API 클라이언트의 인증 갱신 재요청에서도 같은 키를 유지한다. 기존 Authorization 검증을 우회하지 않는다.
- 일간·주간·월간 미션은 서버 상태와 개별 대상 기간을 표시한다. 월말 마지막 주 집계 지연, 전주와 현재 주의 다른 기간을 구분한다. 경건 제출 링크는 해당 주로 진입한다. 커피·밥은 무벌금에서 제외한다.
- 계정/캠퍼스/세션별 Provider remount, 이전 응답 차단, foreground 재조회, 쓰기 요청 직렬화 및 오류 후 재조회 지원.
- 기존 개발 모드 공개 가드는 유지한다. main/스토어 공개와 예수님·시즌 캐릭터는 변경하지 않는다.

## 연동 중 수정
1. 서버 판매 단가를 확인할 API가 없어 백엔드 #274 GET /api/v1/companions/sale-prices를 보완했다. 기존 DB·가격 정책은 그대로다.
2. 캠퍼스 region=null인 실제 주간 제출 성공 응답을 프론트 파서가 거부했다. nullable 값을 빈 표시 문자열로 정규화하고 회귀 테스트를 추가했다.
3. 전체 테스트의 공지/투표 링크 미리보기가 실제 faithlog.app에 접속할 수 있어 자동 승인 검토가 거부했다. 원인인 미리보기 fetch mock 누락을 수정했다. Vitest setup에서 모의 처리하지 않은 HTTP는 실제 전송 전에 차단·실패시키며, 명시적 실제 QA에서는 지정한 loopback origin만 허용한다.
4. 새 SecureStore adapter는 사용할 때 모듈을 로드해 인증 유틸 단위 테스트 import가 네이티브 초기화를 유발하지 않도록 했다.

## 검증
- 타입 검사/린트 성공, 외부 통신을 차단한 전체 Vitest:253개 파일 성공·실제 HTTP용1개 파일 조건부 제외. 테스트2058개 성공·조건부2개 제외.
- 별도 실제 HTTP 테스트2개 실행·성공: PostgreSQL17.6의 독립 DB + develop 백엔드 소스 및 판매가 보완을 실행했다. 인증·서버130종·보유·판매가, 정원 버전 충돌, 판매 마지막1마리, 출석/캘린더 저장 및 수령/최종 제출, 응답 유실 후 같은 요청 키로 뽑기1회 차감·결과1회 지급,10회 뽑기, 서버 이력 확인.
- 실제 React 페이지/Provider + 실제 HTTP로 월간300P 수령, remount 후 상태 복원, 미보유 배치403·다른 캠퍼스403 확인. 네이티브 저장소는 주입 가능한 메모리 adapter로 대체했다. 계정 교체 후 오래된 응답 무시·실패 보상 비적립·중복 탭 직렬화는 별도 Provider4개 단위 테스트로 확인.
- 동일 독립 PostgreSQL에서 CompanionPostgresQaTest5개 실제 실행·성공. 판매가 신규 조회의 인증/단가/REST Docs 포함.
- 운영 Supabase와 실제 사용자 포인트·동물은 테스트에 사용하지 않았다. DB 마이그레이션 추가 없음.
- agent.md의 .harness 문서는 이 checkout에 존재하지 않았다. 실제 iOS/Android 기기 시각·터치·성능, SecureStore 실기기 복원, 스토어 빌드·운영 배포는 미실행.

GitHub CI 및 최종 develop SHA는 검증 완료 후 PR에 기록한다. 이번 문서는 실제 수행 범위와 환경 제한을 구분한다.
