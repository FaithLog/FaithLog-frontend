# #327 미션 및 정원 API 대기 감소

수령마다 전체 경제 상태 11개 이상 GET을 기다리던 흐름을 제거했다. 출석/주간·월간은 POST 응답의 잔액·미션 상태를 적용하고, 일간은 POST 상태와 지갑 GET 1회만 사용한다. 최신 develop의 정원 자동 일괄 저장 및 PUT 응답 반영은 그대로 유지한다. 초기 진입·수동 확인·복귀·실패 복구·뽑기·판매는 전체 재확인을 유지한다.

최소 요청 횟수(인벤토리 1페이지): 출석/주기 미션 12→1, 일간 미션 12→2. 실패/타임아웃 시 로컬 포인트를 임의 가산하지 않는다. 반복 탭 방지와 계정 교체 후 오래된 응답 무시를 유지한다.

검증: 응답 적용 및 전체 재조회 미호출, 서버 지갑 확인 실패, 정원 중복 탭, 계정 전환, 기존 전체 typecheck/lint/test(2071 passed, live 2 skipped) 통과. 실제 HTTP 연결 QA는 V32 기본 1000P가 있는 고정된 백엔드 커밋을 사용하고 지급을 수동으로 중복 생성하지 않는다. 버전 1.3.0을 유지한다. 최신 develop의 드래그 비저장 및 700ms 정원 자동 일괄 저장 동작을 보존한다. 실제 운영 ms/p95 개선은 측정 전 주장하지 않는다.
