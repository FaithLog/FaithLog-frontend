# #299 오류 원인과 후속 조치 안내

경건생활 제출이 활성 벌금 납부 계좌 미등록으로 실패했으나 앱이 HTTP 400을 일반 입력값 오류로 바꾸어 원인을 숨겼다. `BILLING_REQUIRED_PAYMENT_ACCOUNT_MISSING`은 서버가 이미 제공하는 코드이므로 API 계약 변경 없이 프론트 안내를 수정했다.

- 공통 오류 정책에 서버의 알려진 오류 코드 175개에 대한 신뢰 가능한 고정 문구를 추가했다. 원인, 사용자가 확인할 항목, 관리자 또는 담당자에게 요청할 작업을 안내한다.
- 알려진 코드 안내는 화면의 일반적인 오류 문구와 서버 상세 메시지 노출 옵션보다 우선한다. 알 수 없는 코드는 기존 안전한 기본 안내를 유지한다. 세션 만료와 네트워크 오류는 도메인 코드보다 우선한다.
- 밥 정산의 별도 400 처리도 공통 코드 안내를 먼저 확인한다.
- 공지 조회·관리·카테고리 작업, 목홀타 조회·저장·목장 관리, 주간자료에서도 알려진 원인 안내가 일반 실패 문구로 사라지지 않도록 연결했다. 알려지지 않은 실패는 해당 작업의 기존 안내를 유지한다.
- 목홀타 조회 실패 시 오류가 폼 안에만 있어 보이지 않고 '담당하는 목장이 없습니다'가 표시되던 문제도 수정했다. 조회 실패는 실제 빈 목록과 구분하고 재조회 버튼을 제공한다.
- 경건생활 제출의 계좌 누락 오류는 벌금 계좌 등록/활성화 주체가 캠퍼스 관리자임을 설명한다. 오류 카드에 입력을 초기화하는 재조회 버튼을 제공하지 않는다. 현재 체크와 지각 시간을 유지하고 설정 후 기존 제출 버튼으로 재제출할 수 있다. 화면을 나간 뒤에도 보존된다는 의미는 아니다.
- 버튼 문구는 실제 수행하는 재조회 동작으로 통일했다. 관리자 설정 화면으로 이동하는 것처럼 표시하지 않는다.

## 검증

- RED: 오류 정책 회귀 테스트 7개가 기존 일반 입력값/충돌/권한 안내로 실패하는 것을 확인했다.
- 실제 HTTP 응답 정규화에서 계좌 누락 코드의 안내가 보존되는지 검증했다.
- 화면 컴포넌트 테스트에서 체크와 지각 시간 입력 → 계좌 미등록 제출 실패 → 입력 유지와 해결 안내 → 같은 요청 본문으로 재제출 성공을 검증했다.
- 알 수 없는 코드, 서버 상세정보 비노출, 인증/네트워크 우선순위, 밥 정산 안내를 검증했다.
- `npm run typecheck`: 통과.
- `npm run lint`: 오류 없음. 기존 `DevotionScreen.tsx`의 미사용 `screenMode` 경고 1건 유지.
- `npm test`: 235개 파일, 1,926개 테스트 통과.

## 검토 범위와 한계

서버 오류 코드와 상태, 벌금 계산·계좌 연결 정책, DB, 권한, 배포 설정은 변경하지 않았다. 알려지지 않은 코드와 일반 필드 검증 오류는 기존 기본 안내를 사용한다. 별도 오류 문구를 직접 사용하는 화면의 개별 안내는 공통 정책을 호출하는 부분에 한해 적용된다. iOS/Android 실기기 시각 검증과 운영 배포는 수행하지 않았다.
