# 동물 친구 프론트

이슈 #315. 기존 디자인과 하단 탭을 유지하며 홈 정원·동물 관리·미션·뽑기·중복 판매를 제공하는 프론트 단계다. 합성은 포함하지 않는다.

## 확인 방법과 노출 범위

- `npm start`로 개발 빌드를 실행하고 사용자 홈을 연다.
- 개발 모드(`__DEV__`)에서 홈 상단에 최대 5마리가 자유롭게 움직이는 공간과 `동물 관리 / 미션 / 뽑기`가 표시된다. 기존 집계는 아래로 내려간다.
- 정식 스토어 빌드에서는 이 체험 기능을 숨기고 기존 홈 순서를 유지한다. 백엔드 연결 없이 실제 재화처럼 노출하지 않는다.
- `CompanionProvider`는 로그인 세션·사용자·캠퍼스별로 초기화된다. 초기 1,200P와 동물은 예시다. 서버·디스크에 저장하지 않으며 기존 경건·납부·투표 데이터를 수정하지 않는다.
- 개발 모드에서도 모든 화면에 체험 상태를 표시한다. 미션의 완료 상태는 샘플이며 기존 페이지에서 체크하거나 투표해도 체험 미션 상태는 자동으로 바뀌지 않는다.

## 화면

- 홈: 별도 카드·장식 배경 없이 실제 `BibleFriendDesignSprite` 최대 5마리가 각자 목적지를 정해 걷고 쉰다. 누르면 반응, 드래그 중 들림, 놓으면 착지 후 대기. 영역 경계 제한·이웃 양보·화면 크기 변경 대응. 드래그하는 동안만 부모 홈 스크롤 잠금. 놓은 상대 위치는 세션 내 페이지 이동 후에도 복원한다. 접근성 이동 동작도 제공한다. 정원을 벗어나면 타이머 제거, 앱 백그라운드에서 정지, 모션 줄이기 지원.
- 동물 관리: 배치·해제, 보유/중복/전체 도감 필터, 12종씩 페이지 나누기, 상세 및 수량별 판매. 마지막 한 마리는 유지하며 배치 중인 디자인도 한 마리가 남는다. 판매 확인 전 취소 가능.
- 미션: 일간·주간·월간 탭. 준비/미완료/집계 대기/수령 완료. 한국 시간의 일자·월요일·월 경계로 체험 수령 키 분리. 불완료 활동은 기존 경건·투표 화면으로 이동.
- 뽑기: 1개 100P / 10개 1,000P. 실제 에셋 130종과 기존 가중치 설정 사용. 알 집합, 들썩임, 빛 수렴, 균열, 껍질 분리, 파편, 캐릭터 상승·착지, 등급별 파동, 결과와 보유 개수. 건너뛰어도 전체 결과와 보유 개수 유지.
- 같은 세션의 페이지 이동에도 지갑·보유·수령 상태를 공유한다. 뽑기/판매 중복 이벤트에는 트랜잭션 ID를 적용한다.

| 기간 | 미션 | 포인트 |

| 일간 | 출석 | 10 |
| 일간 | 큐티 / 기도 / 말씀 | 각 30 |

## 백엔드 연결 계약

아직 엔드포인트를 가정하거나 호출하지 않는다. 후속 작업에서 다음 데이터를 서버와 합의한다.

1. 스냅샷: 포인트, 디자인별 보유 수량, 배치 디자인 ID 0~5개, 서버 기준 기간 키와 미션 진행·수령 상태, 공식 판매가·뽑기 비용·확률 정책 버전.
2. 미션 보상: 서버가 활동 원본과 회원 가입일·기간·권한을 검증하고 기간당 1회 지급한다. 투표가 없는 주의 정책을 정의한다. 벌금 없음은 기간 종료와 집계 확정 후 결정하며 납부 완료와 구분한다. 월간 제출 대상 주차도 서버가 계산한다.
3. 뽑기: 수량은 1 또는 10, 클라이언트 작업 ID를 전달한다. 서버 트랜잭션에서 잔액 검증·차감·추첨·보유 증가를 함께 확정하고 전체 결과와 최신 스냅샷을 반환한다. 프론트가 받은 결과만 연출한다.
4. 판매: 디자인 ID, 양의 정수 수량, 작업 ID를 전달한다. 서버가 최신 재고·마지막 한 마리 유지·가격을 검증하고 차감·포인트 지급을 함께 확정한다. 클라이언트가 제시한 가격을 신뢰하지 않는다.
5. 배치: 보유한 디자인 ID만 허용하고, 중복 없는 최대 5개를 서버가 검증한다.
6. 재시도/복귀: 같은 작업 ID는 같은 결과를 반환한다. 타임아웃이나 앱 종료 후 서버의 확정된 작업 내역으로 복구한다. 체험 reducer를 실제 정산 로직으로 사용하지 않는다.

연결 시 `isCompanionPreviewEnabled`, 샘플 지갑/재고, `getDemoMissionStatus`, 로컬 추첨·차감·판매·수령 reducer를 서버 어댑터로 교체한다. 공식 가격과 실제 지급이 준비된 뒤 체험 안내를 제거하고 정식 노출한다.

## 검증과 남은 확인

관련 동작 테스트, 타입 검사, 린트, 오프라인 iOS/Android Metro export로 확인한다. 실제 기기의 성능·터치·큰 글씨·화면 전환·시각 품질은 후속 QA가 필요하다. 기존 전체 테스트의 로컬 실행은 외부 faithlog.app 접속 가능성으로 자동 검토가 차단했으므로 전체 통과로 보고하지 않는다.
